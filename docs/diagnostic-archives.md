# Очищенные диагностические архивы агента

Администратор открывает карточку хоста → «Диагностика агента» → «Запросить
очищенный архив». Запрос создаётся для каждой действующей персональной
учётки; агент получает его в обычном ответе диагностики. После приёма
появляется ссылка на ZIP. Старый агент игнорирует запрос; интерфейс ожидает
связи до истечения часа. Снимок метрик по прежней кнопке работает отдельно.

## Состав и очистка

Сервер создаёт ZIP с двумя фиксированными именами: `diagnostics.json` и
`README.txt`. Агент отправляет JSON по закрытой схеме, а не произвольный ZIP.
Неизвестные поля и коды отклоняются. Внутри:

- до 128 безопасных warning/error событий собственной учётки, включая уже
  подтверждённые события сервера за последние 14 дней;
- до 16 сохранённых этапов операций обновления/отката своей учётки;
- сводки журналов uploader/terminal, стандартного Windows session-service и
  MSI/rollback Guard и обычного MSI-updater: число строк, warning/error, коды завершения MSI.

Очистка выполняется проекцией: исходные строки логов и исключений вообще
не сериализуются. Секреты, URL, пути, имена пользователей, командные строки,
конфиги, credentials, записи, транскрипты и содержимое сессий не читаются для
архива. Числовой код MSI извлекается только из `MainEngineThread is returning`;
это диагностическое наблюдение, а не доказательство успеха установки.
Произвольные тексты Info/Debug, stack trace и полный MSI-журнал в архив
не входят. Такой архив не заменяет локальный разбор полного журнала.

## Ограничения

При сборе выбираются не более двух новых файлов на каждый разрешённый
источник из первых 512 имён. Читается не более последнего 1 МиБ каждого файла
и 20000 строк. Для обычного updater дополнительно проверяются два новых
каталога версий из первых 512 в текущем UpdateDir; всего до восьми сводок. Символические ссылки/reparse points, включая родительские
каталоги, не читаются. Недоступный журнал пропускается; отсутствие сводки не
доказывает отсутствие ошибок. `Truncated` означает ограниченный фрагмент.
Для нестандартного каталога Windows session-service сводка может отсутствовать;
журналы uploader/terminal берутся из их текущего LogDir. Начало/конец фрагментов
не являются полной временной шкалой. Часы станции могут быть неверными;
CollectedAt в полученном архиве — время серверного приёма.

Тело запроса ограничено 128 КиБ до разбора JSON. На сервере хранится один
последний запрос/архив на credential. Запрос действует час; незавершённый
запрос повторно не создаётся. После готовности следующий можно запросить
через пять минут с момента предыдущего запроса. Новый запрос заменяет прежний
архив. После получения архив доступен сутки; повтор доставки не меняет байты
и не продлевает срок. Просроченные/отозванные архивы скрываются сразу, очистка
таблицы выполняется обычным retention. Это логическое удаление, не гарантия
стирания байтов SQLite/WAL или резервных копий.

## Доступ и совместимость

Запрос, список и скачивание доступны только admin. Operator/viewer не
получают ZIP, даже если видят диагностику хоста. Проверка роли действует и
на прямых URL. Запрос и скачивание записываются в аудит без содержимого
архива; ответы имеют `Cache-Control: no-store`. Агент загружает отчёт только
по действующей персональной учётке и ID собственного запроса. Общий API token
не принимается. Отзыв credential закрывает доступ к её архиву.

Нужны новый агент и сервер с миграцией схемы 31. Прежние поля диагностики,
метрики и обслуживание совместимы. Недоставка архива повторяет сбор при
следующем опросе и не меняет решения об обновлении/восстановлении агента.
Стендовая проверка этой партии отложена по указанию оператора; production и
релизные теги не изменяются, PR создаётся без CI.

## Локальная проверка 2026-11-05

Прошли 196 тестов агента и семь браузерных сценариев на настоящем локальном
сервере. Полный серверный набор — 768/769; единственный отказ требовал
добавления новых маршрутов в контрольный список EndpointPolicyTests. После
его обновления четыре теста политик и полного цикла архива прошли. Сборки
сервера, GuardRepair и TerminalAgent — без предупреждений; переводы, JS и
shell syntax проверены. Native MSI/reboot и общий стенд не выполнялись.

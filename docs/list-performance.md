# Списки консоли и программ: загрузка порциями

«Консоль» запрашивает `page=true&sessions=true&limit=50`. Ответ — `items` и
`nextCursor`. Курсор содержит пару started_at/id, сортировка — по убыванию обоих
полей. Новые сессии перед первой страницей не сдвигают уже начатую пагинацию;
обновить список целиком можно штатной кнопкой. Изменение времени уже загруженной
сессии или удаление во время просмотра не создаёт снимок всей БД: актуальный
список получается после обновления. Полный COUNT не вычисляется.

Список возвращает превью ввода до 768 символов и `inputTruncated`. Поиск продолжает
использовать полный search_text, включая дочерний вывод. Полный ввод загружается
при раскрытии или открытии сессии. Служебные строки группируются среди уже
загруженных страниц; при дописывании соседние одинаковые группы объединяются.
Усечённые команды не объединяются: одинаковый префикс не доказывает равенство.
При смене фильтра выбор и раскрытые строки сбрасываются. Загрузка следующей
страницы и её ошибка сохраняют уже показанные строки. Старые запросы отменяются,
запоздалые ответы не дописываются к новому фильтру.

Подсказки хостов используют `/api/host-names?q=...&limit=50`, без полного inventory.
Группы viewer проверяются при каждом запросе; общий кэш содержимого консоли
и подсказок не вводился. Старый API без page=true по-прежнему возвращает массив.

Настройки программ сначала получают лёгкую конфигурацию через
`/api/settings/app-kinds?seen=false`, независимо от статистики окон. Каталог
процессов — `/api/settings/app-kinds/seen?limit=50&q=...`. Агрегат за 30 дней
строится один раз в минуту, параллельные запросы объединяются. Снимок содержит
до 10000 процессов, имена объединяются без учёта регистра. Пагинация привязана
к снимку и запросу поиска; снимок живёт до 10 минут, в памяти не больше 10 снимков.
Устаревший курсор даёт 409 с предложением обновить страницу. Настройки и права
не кэшируются, несохранённые правки сохраняются при поиске и дописывании страниц.
Стандартные типы и явные правки доступны без ожидания статистики. API только admin.

## Локальный SQL-замер 2026-11-02

Это **синтетические данные**, а не production и не тестовый стенд: 1 000 000 окон
с 1000 именами процессов, 20000 корневых сессий с вводом по 8198 байт.
Пять повторов, медиана тёплых запусков; первый запуск не считается холодным
кэшем ОС. Измеряется SQLite и сериализация строк в JSON, без HTTP DTO, сети,
группировки и браузерной отрисовки. Реальные задержки пока не измерены.

| Запрос | До, мс | После, мс | Примечание |
|---|---:|---:|---|
| Начальная консоль | 5.29 | 0.16 | 300 полных строк → 51 компактная, одна служит признаком следующей страницы |
| Компактная консоль с поиском | 0.36 | 0.28 | Одинаковая выборка 51 строки, проверка нового индекса |
| Новый агрегат программ | 1301.89 | 658.88 | Один и тот же запрос до/после покрывающего индекса |

JSON SQL-строк начальной консоли: 4,938,570 →
42,075 байт. Это не размер HTTP-ответа: прежний SELECT *
содержал также search_text, который DTO не отдавал. Фактическое снижение трафика
будет меньше и зависит от длины команд и дочерних записей.

EXPLAIN: начальная консоль использует `ix_terminal_roots_page`, подсказки сессий
хоста — отдельный индекс `(host, started_at DESC, id DESC)`. Каталог использует
`USING COVERING INDEX ix_activity_app_catalog (ts>?)`, временные B-tree для
GROUP BY и ORDER BY сохраняются. Вариант индекса с выражением site IS NOT NULL
не выбран: он не дал покрывающего плана. Старый агрегат без объединения регистра
и с LIMIT 300: 774.06 мс; новый возвращает 1000 процессов,
поэтому сравнение скорости одного только индекса выполнялось на одинаковом запросе.
Повторные страницы действующего снимка SQLite не читают.

До общего стендового прогона остаются реальные HTTP/SQL/отрисовочные замеры,
холодный старт на репрезентативной копии БД, большие дочерние истории и live-нагрузка.
Ориентир для согласования после этого прогона: полезная первая страница до 1 секунды
на тёплом сервере; это цель проверки, а не подтверждённый production SLA.

## Полноэкранный плеер

Кнопка «Полный экран» открывает постоянный контейнер двух видеослотов. Смена
активного слота сохраняет fullscreen контейнера. Если браузер открыл fullscreen
самого video (штатный/iOS режим), новый src назначается тому же видимому элементу,
который не получает класс preload. Скорость, мониторы, перемотка и версии URL
сохраняют существующую логику. Локальный Chromium проверяется Playwright;
нативные Safari/iOS и Firefox/Edge требуют отдельной проверки по доступности.

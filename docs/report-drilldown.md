# Отчёты: расшифровка показателей и переходы

Из сводки можно открыть хост, из таблицы учёток — её приложения, из приложения
— связанные учётки или исходные интервалы. «Показать детали» открывает
интервалы активного окна. Вкладка «Исходные интервалы» переключается между
записями экрана и активным окном. Путь отчёта показывает текущие хост, учётку
и процесс; ссылка «Сводка» снимает эти фильтры, сохраняя период и группу.

Период, группа, хост, имя учётки, процесс, рабочие часы и вкладка находятся
в URL. Они сохраняются при переходах, перезагрузке и возврате браузером.
Часовая зона общая для сервера и указана в отчёте; выбор зоны браузера
не меняет расчёт. Источники показывают также исходные UTC-границы.

## Показатели

Определения и контрольный пример — [report-metrics-audit.md](report-metrics-audit.md).
В интерфейсе доступны пояснения «Как считаются показатели».

- Время записи — объединение интервалов отдельно на каждом хосте. Несколько
  хостов суммируются: это не уникальное календарное время человека.
- Интервалы активного окна — сумма наблюдений по сессиям на шкале записанного
  видео, а не время жизни процесса или доказательство ввода пользователя.
- Учётка в новых таблицах определяется парой «хост + имя из сессии».
  Одинаковые имена на разных хостах не объединяются в одного человека.
  Приложения группируются по имени процесса; подпись/путь бинарного файла
  в этих данных отсутствуют, тождество программ не подтверждается.
- Фильтр программы действует на интервалы активного окна и список связанных
  учёток. Время записи хоста/учётки остаётся отдельным показателем.
- Исходные секунды не округляются; сводка округляет отображаемые секунды,
  интерфейс — время для чтения. Доли секунды в деталях могут отличаться от
  округлённой цифры. Количество сегментов в новых строках учёток — число
  начал, учтённых часовыми фактами в выбранных часах.

Строки исходников могут пересекаться: их длительности нельзя сложить и
получить объединённое время записи. У активного окна суммы складываются
по сессиям, поэтому параллельные записи добавляют время. Программа с типом
«Не учитывать» показана в деталях с причиной исключения; интервалы вне
рабочих часов тоже явно исключены. В сводку они не входят.

## Актуальность и полнота

Сводка использует существующие заготовки, источники читаются из текущей БД.
Поздний приём, удаление или смена настроек могут изменить цифры; время
обновления и очередь пересчёта указаны отдельно. Очередь ограничена группами,
периодом и хостом текущего пользователя. Страницы не являются неизменяемым
снимком БД: после изменения данных нужно обновить отчёт.

Шкала показывает интервалы только текущей страницы. Пробел означает
отсутствие записи с неизвестной причиной. Полнота численно не измерена:
нет процента покрытия и предположения о простое. Пустой период обозначает
отсутствие исходных данных, а не отсутствие работы человека.

`Открыть запись` передаёт ID сегмента и смещение. При параллельных сессиях
выбирается именно этот сегмент; отсутствующая запись не заменяется соседней.
Удалённые строки не доступны в источниках; недоступный файл обрабатывается
существующим плеером. Права на видео повторно проверяются его API.

## API и объём данных

`GET /api/reports/source` принимает from/to (даты включительно, до 366 дней),
kind=records/windows, groupId, host, user, process, workHours, limit и cursor.
Политика Recordings и ViewerScope действуют на запрос целиком, включая
счётчики. Неавторизованные хосты не попадают в строки/метаданные. Ответы
не кэшируются; просмотр аудируется.

Страница по умолчанию содержит 50 источников, максимум — 100. Cursor задаёт
пару времени и ID, поэтому одинаковые времена не теряют записи. В браузере
хранится только текущая страница; кнопки «Назад/Далее» меняют курсор.
Используются существующие индексы времени/хоста и segment_id. Количество
новых строк учёток ограничено 1000 с явным сообщением об ограничении.
Проверка на синтетических 100000 интервалах контролирует размер страницы,
отсутствие повторов и выполнение двух выборок в пределах десяти секунд.
Она не заменяет замер на production-объёме и общий стенд.

Источники рассчитаны на штатные сегменты не длиннее суток, как действующие
заготовки. Время окна связано со шкалой видео и pre-roll, а не точным
календарным интервалом. Существующие заготовки переходных суток DST используют
одно смещение в середине дня; их точность в таких зонах не подтверждается.
Это ограничение показано в интерфейсе. Новая расшифровка не утверждает
исправление DST и не объединяет учётки через SID/каталог, которых нет в данных.

Схема БД и сбор данных агента не меняются; прежние поля сводки сохранены
для совместимости, новые таблицы UI используют accounts с контекстом хоста.
Общий стенд отложен до завершения партии по указанию оператора. Production,
релиз и теги не меняются, PR — без CI.

## Локальная проверка 2026-11-06

Финальная сборка сервера с security analyzers — ноль предупреждений/ошибок.
Полный набор: 776/776 серверных тестов. Внутри него — проверки пересечений,
рабочих часов, исключённых программ, идентичностей, групп и пагинации на
100000 интервалах. Прошли 13 разных браузерных сценариев отчётов/плеера;
после уточнения подписей и CSV повтор семи затронутых сценариев тоже прошёл.
Переводы, JS syntax, bundle shell syntax и diff check прошли. Общий стенд,
фактические данные production и переходные сутки DST этим не проверялись.

# Отчёты: источники, определения и расшифровка

Аудит исходников 2026-11-05: `Reports.cs`, `ReportFacts.cs`,
`ReportFactsService.cs`, `Db.ReportFacts.cs`, `Db.Activity.cs`, `ActivityLog.cs`.
Это описание текущих источников, а не подтверждение стендовой приёмки.

## Что измеряется

| Показатель | Источник и формула | Ограничение |
|---|---|---|
| Время записей хоста | Объединение `[started_at, ended_at)` всех видеосегментов хоста; затем обрезка периодом/рабочими часами | Наличие записи и движения не доказывает работу человека |
| Время записей учётки | Объединение интервалов отдельно на каждом хосте; сумма по хостам | Параллельная работа на разных хостах суммируется, это не уникальное календарное время человека |
| Интервалы активного окна | Разность следующего `offset_sec` и текущего, у последнего — `duration_sec - offset_sec`; привязка к `ts` | Это шкала записанного видео; реальное календарное время может отличаться |
| Время приложения | Сумма интервалов активного окна с данным process по всем выбранным сессиям | Не время жизни процесса, не доказательство ввода; параллельные записи суммируются |
| Полнота | Наличие исходных записей/интервалов и актуальность пересчёта | Нет источника достоверного процента покрытия или доказанного простоя |

Период задаётся датами включительно в зоне сервера; внутренние интервалы
полуоткрытые. Рабочие часы — понедельник–пятница 09:00–18:00 той же зоны.
Округление выполняется при отображении, исходные секунды сохраняются.

## Найденные ограничения и расхождения

- `session_user` — имя из сессии, а не SID/ID каталога. Нельзя доказывать
  тождество человека совпадением имени. Для раскрытия учётки нужен контекст
  хоста; локальные одинаковые имена разных хостов следует различать.
- `process` — переданное имя процесса, а не подписанный путь/ID продукта.
  Группировка по имени не доказывает, что это одинаковый бинарный файл.
- Текущие приложения суммируют пересекающиеся сессии, хосты объединяют
  записи. Эти суммы не обязаны совпадать и требуют разных подписей.
- Время активного окна связано со шкалой видео, pre-roll получает первую
  известную подпись; это приближённая привязка к календарю.
- Факты пересчитываются асинхронно, поздние записи меняют итоги. Счётчик
  очереди пересчёта сейчас общий и должен быть ограничен правами/периодом.
- При подготовке суток используется смещение зоны в середине дня: для зон
  с DST переходные сутки могут быть рассчитаны неточно. Это следует
  исправить перед заявлением точности для произвольной зоны.
- Строка источника не гарантирует наличие файла: запись могла быть удалена
  или недоступна. Переход к плееру должен обрабатывать отсутствие записи.
- HTTP-ответ сводки не содержит исходных интервалов. Фильтры живут в local
  state браузера и теряются при переходах; нужны параметры URL.

## Контрольный пример

У учётки `HOST-A\\operator` есть записи 10:00–10:10 и 10:05–10:15:
сумма длительностей 20 минут, объединённое время хоста/учётки — 15 минут.
На HOST-B одноимённая локальная учётка имеет запись 10:00–10:10: это отдельная
учётка; сумма времени хостов — 25 минут, календарное объединение — 15 минут.
Если Excel был активным окном по 10 минут в двух параллельных сессиях,
сумма измеренных интервалов Excel — 20 минут, а не 10 минут работы человека.
Пробел 10:15–10:30 означает отсутствие записи, причина простоя неизвестна.

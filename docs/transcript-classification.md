# Классификация транскриптов Windows

## 0.16: выгружается каждый транскрипт, с метками

До 0.16 агент выгружал только транскрипты, доказанные как SSH; остальные
удалял, а неопознанные через сутки уходили в карантин и становились потерей
`transcript-no-4688` (на проде к ноябрю 2026 — 22 тыс. строк с 247 хостов,
почти всё — локальная автоматизация). Теперь каждый закрытый транскрипт
выгружается с двумя метками:

| Метка | Значения | Откуда |
|---|---|---|
| `origin` | `ssh`, `automation` (планировщик, службы), `sql-agent`, `local` (explorer — рабочий стол/RDP), `winrm` (wsmprovhost), `unknown` | цепочка родителей по 4688 (ниже); «Запуск от имени» SYSTEM / NT AUTHORITY\… / машинная учётка `…$` — `automation` без 4688 |
| `mode` | `interactive`, `exec` | командная строка хоста в заголовке: `-Command`/`-c`, `-EncodedCommand`/`-e`/`-enc`, `-File`/`-f` или позиционный аргумент — `exec`; с `-NoExit` — `interactive` |

Не определилось за `UnknownGraceMinutes` (10 мин) после закрытия файла —
выгружается с `origin=unknown`. Идущая SSH-сессия по-прежнему уходит кусками,
остальные — после закрытия. Что не хранить, решает сервер по
`skipTranscriptOrigins` группы/хоста (по умолчанию хранится всё; в выводе
автоматизации бывают секреты). `svchost.exe` запускает и задачи планировщика,
и другие службы — по 4688 их не различить, поэтому одна метка `automation`.

Сервер расшифровывает `-EncodedCommand` (base64 UTF-16LE) для показа и поиска
(`input_decoded`), исходный ввод хранится как есть. Фильтры «Консоли»:
«Тип» учитывает `mode`, «Происхождение» по умолчанию скрывает `automation` и
`sql-agent`. Миграция 33 подтверждает прежние потери `transcript-no-4688`
(строки журнала остаются) и расшифровывает ввод уже сохранённых записей.

Ниже — как определяется цепочка родителей (с 0.15.1); причины Unknown теперь
только в диагностике агента, потерей они не становятся.

## Как принимается решение

Агент сопоставляет заголовок транскрипта с событием 4688: PID, временное окно
и путь исполняемого файла. Новому хосту PowerShell с полным путём в заголовке
не требуется добавление имени в список. Совпадение только PID недостаточно.
Для заголовков с сокращённым именем остаётся совместимость с powershell.exe,
pwsh.exe и SQLPS.exe; неизвестное сокращённое имя остаётся Unknown.

Используется последнее событие PID в окне от 10 минут до 30 секунд после
времени заголовка. Несколько кандидатов с повторным PID после начала
транскрипта, несовпадение пути и противоречивая цепочка не дают разрешение
на выгрузку. Поддерживаются полные пути в кавычках и без них, включая пробелы.

Родители обходятся до 16 переходов, с проверкой имени и времени каждого
события. SSH подтверждается точными именами sshd.exe/sshd-session.exe.
Границы локальной автоматизации — SQL Agent, службы и локальная оболочка
Windows (SQLAGENT, services, svchost, taskeng, taskhostw, explorer).
Неизвестный посредник без достаточной истории не объявляется NotSsh.
Как и прежде, для conhost действует дополнительное окно в одну минуту.

## Сбор и сохранение контекста

Фоновый сборщик независимо от HTTP-регистрации и выгрузки читает 4688,
сопоставляет заголовки новых файлов и сохраняет их происхождение. Долгая
загрузка или недоступный сервер не блокируют этот сбор. Кэш происхождения
защищён от одновременной работы сборщика и загрузчика.

События читаются по именованным XML-полям, а не позициям свойств конкретной
версии 4688. В кэше только время, PID, путь образа и сведения о родителе;
командные строки и содержимое транскриптов не сохраняются в кэш событий.
Для первичной классификации читается не более 64 К символов заголовка.
Полный текст для отправки читается только после подтверждения SSH.

Кэш ограничен 20 000 событиями и 48 часами. За проход читается не более
2000 событий; при отставании следующий проход через секунду, обычно — через
ScanIntervalSeconds (не чаще 5 секунд, по умолчанию 15). Файл кэша сохраняется
не чаще раза в минуту через временный файл и замену. Сохранённые решения о
конкретных транскриптах живут до удаления файлов и не требуют повторного 4688.

Checkpoint содержит RecordID и время события. Если событие исчезло или его
время изменилось (очистка, разрыв или перезапись журнала), доступная история
перечитывается. Уже сохранённые метаданные остаются до возрастного/размерного
лимита. Ошибки чтения повторяются; отсутствие метаданных не превращается в
подтверждение локальной автоматизации. Не существовавшее или уже потерянное
событие этот механизм восстановить не может.

## Причины Unknown

| Код | Что наблюдается |
|---|---|
| event-pending | Недавний запуск либо сборщик ещё дочитывает историю |
| event-missing | Подходящее событие не найдено, причина не доказана |
| history-unavailable | Начало транскрипта старше доступной истории Security |
| event-read-failed | Security не удалось прочитать, сборщик повторяет попытки |
| audit-disabled | Аудит создания процессов выключен **на момент проверки** |
| host-unconfirmed | Для неизвестного сокращённого имени не хватает полного пути |
| process-mismatch | Путь не совпал либо повторный PID неоднозначен |
| ancestry-incomplete | Не хватает подтверждённых родителей |
| ancestry-cycle | Цикл в цепочке родителей |
| invalid-transcript | Неполный/повреждённый заголовок |

Текущий выключенный аудит не доказывает причину исторической потери.
History-unavailable также не доказывает, что нужное событие когда-либо
создавалось. GPO, политики аудита и размер Security автоматически не меняются.

`transcript-diagnostics.json` содержит время, количества по причинам и
состояние сборщика, без команд и текста сессий. Предупреждения группируются
по причинам и выводятся не чаще часа; ошибки обслуживания — не чаще 5 минут.

## Карантин

С 0.16 в карантин попадает только неразбираемый закрытый файл (через час);
Unknown выгружается с `origin=unknown`, а копии Unknown, сохранённые туда
прежними версиями, агент выгружает и удаляет. Ниже — механизм хранения.

Перед удалением исходника: копия, сверка SHA-256, сохранённые метаданные,
запись журнала потерь на диск и повторная проверка, что исходник не изменился.
Ошибка копирования, доступа, переполнение или отказ записи журнала оставляют
исходник в активной папке. Повтор незавершённого переноса не создаёт новую
копию и не продлевает срок её хранения. Имена файлов карантина — хеши;
пути из JSON не используются для удаления. Reparse points в пути карантина не допускаются. Папки карантина и активных
транскриптов не должны пересекаться; неправильная конфигурация отклоняется.

Карантин доступен SYSTEM/Administrators (тот же механизм ACL, что у учётки
агента). Срок — 7 дней, ёмкость — 256 МиБ и не более 2000 сохранённых файлов по умолчанию; при необходимости
освобождения ёмкости удаляются старейшие сохранённые копии. Журнал о том,
что запись не была выгружена, остаётся. Очистка работает и при пустой папке
транскриптов. Карантин не выгружается и не переобъявляется SSH автоматически.

Лимит карантина не ограничивает исходники, которые не удалось перенести;
при таких ошибках нужно проверить локальный диск и права, исходники не
удаляются для имитации успешного восстановления. Это также не меняет
политику хранения открытых транскриптов.

## Сервер и совместимость

Базовая причина потери остаётся transcript-no-4688. Необязательное поле
`detail` содержит один из фиксированных кодов выше; произвольный текст
отбрасывается. Старый сервер сохраняет базовую потерю, игнорируя новый код.
Новый сервер сохраняет его миграцией 25 (nullable host_losses.detail), без
переписывания старых строк и без новых таблиц.

`GET /api/inventory/{name}/losses/summary?all=false` — количества по причинам,
первое/последнее сообщение и число непринятых, до 64 групп. Сводка считается
по всему журналу хоста, независимо от ограничения подробного списка в
500 строк. Применяются обычная аутентификация и ограничения групп viewer.
`all=true` включает принятые события. Сводка показана в карточке хоста;
подробные записи и штатное принятие уведомлений сохранены.

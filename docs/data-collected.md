# Какие данные собирает Watcher

Справка для ИБ, юристов и кадровой службы заказчика: что именно записывает
агент, где это хранится, кто видит и как сократить объём. Текст уведомления
сотрудников и правовые основания организация готовит сама; здесь только факты
о системе.

## Что собирается

| Данные | Где | Когда | Настройка |
|---|---|---|---|
| **Видео экрана** — снимок рабочего стола пользователя, по умолчанию 640×480, 2 кадра/с | Windows: каждая сессия пользователя (в том числе RDS); Linux: графическая сессия X11 | только при изменениях на экране (детектор движения) плюс несколько секунд до них | конфиг группы: разрешение, частота, порог движения; `allowUsers` / `excludeUsers`; расписание и исключения (ниже) |
| **Активное окно** — имя программы и заголовок окна на переднем плане, при каждой смене; у браузера (Windows, агент 0.14.3+) — ещё **домен** активной вкладки из адресной строки (`mail.example.com`, без пути и параметров адреса) | вместе с видео | пока пишется видео | `activity`: `full` / `process` (без заголовков и домена) / `off` |
| **Ввод в консоли** — набранные команды | Linux: SSH и консоль (`pam_tty_audit`); Windows: все сессии PowerShell (транскрипт) с меткой происхождения — SSH, планировщик/службы, SQL Agent, рабочий стол, Remoting, «не определено» (0.16; до этого — только SSH); что из этого не хранить — `skipTranscriptOrigins` в конфиге группы | у всех пользователей, кроме исключённых в конфиге группы | `allowUsers` / `excludeUsers` (общие с экраном); выключить целиком — `--no-console` у `watcher-agent-setup`, Windows — `-TerminalAudit 0` / `TERMINALAUDIT=0` |
| **Вывод в консоли** — всё, что выводилось на терминал | Linux: интерактивный shell (`script(1)`); Windows: транскрипт PowerShell | то же | то же |
| **Команды без терминала** — запущенные процессы с аргументами и рабочим каталогом | Linux: SSH-сессии без терминала (`ssh хост 'команда'`, scp, автоматизация) — auditd, правило `watcher-exec` | то же | то же; аргументы командной строки пишутся как есть — пароль, переданный в аргументе, попадёт в запись |
| **Метаданные** — имя компьютера, пользователь сеанса, IP-адрес станции, время начала и конца записи, версия агента | сервер | с каждой записью и heartbeat раз в минуту | — |

**Android (корпоративные устройства, агент в разработке — Этап 4):** пока
агент — обычное приложение с постоянным уведомлением «Устройство
корпоративное»; с Этапа 5 — владелец устройства (device owner), и Android
сам постоянно показывает пользователю, что устройство принадлежит
организации. Агент собирает: какое
приложение выходило на экран и уходило с него (время, имя пакета), установки
и удаления приложений с источником установки, перечень установленных
приложений с версиями (раз в сутки и при изменениях), состояние устройства
(версия Android и патча безопасности, тип сети — без имени Wi-Fi, заряд
батареи, включён ли экран, есть ли у агента доступ к статистике
использования), объём трафика по приложениям (байты, без адресов
и содержимого). У агента-владельца устройства дополнительно: сетевой
журнал (домены DNS и адреса соединений с приложением-инициатором, агрегировано
по приложению; без содержимого трафика) и журнал безопасности системы
(подключения adb, разблокировки, загрузка, изменения политик). В веб-UI это сводка устройства за день (вкладка «Устройство»). Местоположение, контакты, сообщения, звонки, содержимое
экрана и файлов не собираются. Хранится на сервере тем же сроком, что
записи; видят роли с доступом к записям, viewer — только свои группы.

Не собираются: звук, нажатия клавиш вне консольного аудита, буфер обмена,
содержимое файлов, веб-трафик, полные адреса страниц (только домен), переписка как текст (только то, что видно на
экране в видео).

## Когда запись не ведётся (H8)

Задаётся в конфиге группы или хоста (веб-UI, «Конфиг»):

- **Расписание** (`schedule`) — запись только в указанные дни и часы по часам
  станции, например «пн-пт 09:00-18:00». Вне расписания экран не снимается.
- **Исключённые программы** (`excludeProcesses`) и **окна по заголовку**
  (`excludeTitles`): пока такое окно на переднем плане, запись на паузе — нет ни
  кадров, ни имени окна в активности. Подходит для менеджера паролей,
  банк-клиента, личной почты, медицинских порталов.
- **Сайты** (`excludeSites`, Windows-агент 0.14.3+): пока в браузере открыт
  сайт из списка (домен с поддоменами) — запись на паузе. Надёжнее правила по
  заголовку.
- Windows: экран заблокирован или открыт защищённый рабочий стол (UAC) — запись на паузе.

Ограничения: исключение срабатывает по окну **на переднем плане** — если
исключённое окно видно рядом с активным, оно попадёт в кадр. Переключение
окна замечается за доли секунды (раз в 0,5 с по умолчанию). Расписание и
исключения касаются записи экрана; консольный аудит ведётся для заданных
пользователей всегда.

## Где хранится и сколько

- На станции — только до выгрузки (очередь с ограничением по размеру), затем
  удаляется.
- На сервере — `RetentionDays` дней (по умолчанию 30) или свой срок группы,
  плюс лимиты по объёму и свободному месту (`docs/configuration.md`).
- Legal hold — записи хоста за период не удаляются, пока отметка действует
  (разбирательство); установка и снятие — в журнале доступа.
- Журнал доступа — отдельно, `AuditRetentionDays` (по умолчанию 365): кто и
  когда смотрел записи, искал по консоли и окнам, выгружал.
- Передача станция → сервер — HTTPS (`docs/install.md`, «HTTPS для агентов»).

## Кто видит

- Роль **viewer** и **admin** — записи; viewer можно ограничить группами хостов.
  **operator** записей не видит (только настройки парка).
- Выгрузка архивом — отдельное право, по умолчанию ни у кого (H7).
- Каждый просмотр видео, открытие консоли, поиск по консоли и окнам и
  выгрузка записываются в журнал доступа (`#/settings/audit`); его можно
  отправлять в SIEM.
